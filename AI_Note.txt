2. Design advice for the implementation
---------------------------------------

- Runtime state: Env as an immutable map from names to Ref (rho), Ref as a
  mutable location, and the store sigma as the set of all Refs. Fixed the Ref
  class so its value is a settable property.
- Outcome as a record hierarchy (O_Normal | O_Ret(Value)) instead of an enum
  with a nullable value.
- Closures hold a block body, so lambdas (wrapped as {Ret e;}) and functions
  share one representation.
- Where to keep Delta (built once in P-Prog, kept out of rho), and ways to pass
  it to E_Field.
- Statement execution must return (Outcome, Env) so S_Decl can extend the
  environment; blocks discard the returned environment (scoping).
- Types are erased at run time: S_Decl, E_Lambda and Param keep their types for
  the type checker only; runtime type checks are not part of the rules.
- Nat subtraction: originally flagged that it wraps around in C# and that the
  first fix (flooring at zero) silently produces a wrong answer; worked through
  the options and settled on Nat - Nat = Int (total and honest, consistent with
  unary negation widening Nat to Int). Noted the knock-on effects: idiomatic Nat
  recursion (factorial counting down) no longer type-checks, and the runtime had
  no coercion between numeric tags.
- Pointed out issues to decide or document:
    - && and || are strict, not short-circuiting, and are missing from the
      report's grammar;
    - the recursive S_While will overflow the stack on long loops;
    - records containing lists (T_Func, V_Record) compare lists by reference.
- P_Prog: pointed out that Establish() was not idempotent (calling it from
  the type checker and again from Execute duplicates every function), that
  the public mutable lists broke record equality, and that Env (runtime
  state) does not belong on the AST; suggested computed read-only Funcs,
  Records and Stmts derived from Commands.

4. Report: type system
----------------------

Used as a tutor and checker while I wrote the typing rules. I drafted the
TE-/TS- rules; it corrected them and wrote TP-PROG.

- Proposed the shape of the statement typing judgement: a context-threading
  form Gamma |-_{tau_r} s -| Gamma', where only TS-DECL/TS-READ grow the
  context and the expected return type tau_r is carried as a subscript on the
  turnstile, plus a separate block judgement that exports no context (mirroring
  the runtime discarding a block's inner environment).
- Rule corrections made to my drafts:
    - TE-LAMBDA: type the body under the context extended with the parameters,
      and give the lambda a function type rather than its return type;
    - TE-RECORD: added the missing result type (: R) and quantified the field
      premise over i;
    - TS-DECL/TS-READ/TS-ASSIGN: moved tau_r off the output context (it was
      written as Gamma_{tau_r}) onto the turnstile where it belongs;
    - TS-ASSIGN: the lookup premise is membership (x:tau in Gamma), not a
      statement judgement;
    - TS-COND: check both branches, and add the subscript and -| Gamma to the
      conclusion.
- Wrote TP-PROG: function signatures collected into one context so functions
  are mutually visible, each body checked under its parameters with its
  declared return type as tau_r, and the top-level statements checked with no
  return type (tau_r absent) so a top-level Ret is untypable.
- Pointed out there is no TE-APP rule although application is in the grammar,
  and supplied one.
- Explained design questions: that statements have no result type so the
  judgement checks context flow and return agreement instead; that "a return
  outside a function" falls out of tau_r being absent at the top level; and
  that whether a function must return on every path is a separate
  definite-return analysis, not type agreement -- left out, since E_Appl
  already raises a clear error on fall-through.


5. Code: type-checker exceptions and tests
-------------------------------------------

- Reviewed TypeChecker.cs: confirmed the type rules (Widest, Sig, Assignable,
  SameType) and flagged two bugs where the immutable Context's updated copy was
  discarded -- CheckBlock not threading the per-statement context, and
  CheckProgram not rebinding parameters; I fixed both.
- After the typed exception classes were added, wired the specific exceptions
  through TypeChecker in place of the empty TypeException("") throws
  (UnBound/UndefinedType/InvalidCall/UnexpectedType/TypeMismatch/
  NotWellTyped/UndefinedUnaryNegation/Internal). Changed FieldType to take the
  E_Field node so a non-record target reports NotWellTypedException, and split
  S_Return into CheckReturn so a top-level return (no tau_r) is distinguished
  from a wrong return type.
- Wrote the type-checker test suite (126 tests) from the intended semantics,
  driven only through TypeChecker(P_Prog).Check(): a shared TC helper, then one
  file each for operator typing, assignability, expressions, statements and
  whole programs. Expression types are pinned via the return type that accepts
  them (e.g. Nat-Nat must be Int, not Nat; comparisons give Bool).
- Noted but did not test as a failure: S_Decl ignores its type annotation (it
  binds the variable to the initialiser's inferred type), which is inconsistent
  with S_Read and the Assignable checks elsewhere.
- Wrote the parser test suite (77 tests), feeding the parser exact token lists
  (there is no lexer) and inspecting the AST: a shared PT helper, then files for
  expressions (precedence, associativity, unary, ternary, grouping, postfix
  application/field, New, Lambda), statements, declarations/types (including
  function types), program structure, and malformed streams. Used Assert.Equal
  on list-free nodes and piecewise checks where a node holds a list (which
  C# records compare by reference).


6. Code: lexer review and tests
-------------------------------

- Reviewed Lexer.cs against the parser's expectations and fixed four bugs:
  '%' mapped to DIV (should be MOD), '<' to LEQ (should be LT) and '>' to GEQ
  (should be GT); and the shared scratchpad StringBuilder was not reset after
  the double-/single-symbol branches, so a symbol token left stale characters
  that corrupted the next token (e.g. "a := b" emitted a phantom COLON). Added
  a scratchpad.Clear() at the top of each lex iteration.
- Added the missing "Bool" keyword (the parser accepts Bool as a type, but
  without it Bool lexed as an identifier -> T_Record), and made Lex append an
  EOF token so its output is directly consumable by the parser, which loops on
  while(!Check(EOF)). Also unswapped the misnamed singleT/doubleT locals.
- Wrote the lexer test suite (61 tests): single symbols, double symbols with
  maximal-munch checks, int/real literals, keywords vs identifiers (case
  sensitivity), whitespace handling, EOF termination, the scratchpad-leak
  regressions, a representative statement, and unknown-character errors.


7. Example programs
-------------------

- Wrote seven example programs in example_programs/ that together exercise the
  whole language: arithmetic (numeric widening Nat<:Int<:Real, + - * / %, unary
  negate), conditionals (&&/||, comparisons, ternary, If/Else), loops (While +
  assignment), recursion (fact/fib), mutual recursion (isEven/isOdd),
  higher-order functions (Lambda, function-typed params, a function returning a
  function, closures) and records (declaration, New, nested field access, ==),
  plus an interactive io.mpl using Read. Added a README table.
- Verified each by lexing -> parsing -> type-checking, and executing all the
  non-interactive ones (captured output matches: 120/55, closures 201, record
  structural equality True, etc.).
- Chose the examples around two real constraints of the current implementation:
  the lexer has no comment syntax (so the files carry none), and S_Decl binds a
  variable at the inferred type of its initialiser rather than its annotation,
  so counters/parameters are typed to stay Assignable (e.g. recursion uses Int
  params because Nat - Nat widens to Int).


8. Report: lists and subtyping
------------------------------

Cross-checked the new list feature (T_List/T_EmptyList, E_List, E_Index, the
list fields .length/.head/.tail, + as concatenation, Assignable) against the
report and listed what was missing or wrong. I wrote the LaTeX; I applied most
of the type-side myself from its suggestions, and it then wrote the subtyping
part directly into report.tex.

- Diagnosed the gaps/errors: value grammar omitted list values; TE-LIST
  concluded [tau_n] instead of [join of all elements]; E-LIST-INDEX returned
  v_{i-1} (off-by error vs the 0-based Access); no typing rule for $ indexing;
  .length/.head/.tail unspecified (TE-/E-FIELD only covered records); and no
  assignability/subtyping to justify Var xs:[Int]=[] (and Nat->Real decls).
- Designed the fld meta-function (type- and value-level) so e.f generalises to
  records plus built-in list fields as one TE-FIELD/E-FIELD rule, undefined on
  EmptyList; applied by me into the report.
- Wrote the subtyping relation tau <= tau' (S-REFL, Nat<=Int, Int<=Real,
  Nat<=Real, EmptyList<=[tau], covariant lists) matching Assignable, and amended
  TE-APP, TE-RECORD, TE-LAMBDA, TS-DECL, TS-ASSIGN and TS-RET to take an
  assignable (not exact) type, with TS-DECL binding the annotated type so
  EmptyList never leaks into the context. Deliberately no global subsumption
  rule, to stay syntax-directed and match the checker.
- LaTeX: diagnosed compile errors from a cases block (extra alignment tabs,
  missing $, a \small used in math mode, overfull from the wide record case);
  gave clean blocks and rebuilt the PDF to confirm (no errors; pre-existing
  empty-bibliography warning only).
